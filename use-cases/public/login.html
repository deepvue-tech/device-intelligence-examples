Catch credential stuffing at sign-in

Attackers replay leaked username and password pairs, one account after another, from the same machine. Count failures per device rather than per account, and ask a new device for an OTP.

The demo account is demo with password deepvue-demo. Don't use a real password here.

Try to fool it

  1. Sign in as demo / deepvue-demo. A device the account hasn't seen is asked for an OTP.
  2. Sign in again. Known device, no OTP.
  3. Try three other usernames with any password, as a stuffing script would. Then use the right password: blocked.
  4. Turn on a VPN. Even the right password needs an OTP.

Press Forget this device to start over.

Why not per account

A stuffing script tries each account once or twice, so per-account lockouts never trip. All those tries come from a handful of devices.

The SDK collects device and browser metadata, never names, phone numbers or emails. The demo server keeps each device's history in memory for 24 hours, with usernames masked and passwords never stored.
