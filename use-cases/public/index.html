Fraud demos for lenders and fintechs

Four fake apps, each with a fraud attempt you can try yourself and the check that catches it. No sign-up. Open a private window or clear your cookies halfway through: the device is still recognised.

  • Loan application

    Someone is declined, raises their income and applies again from the same phone.

    Catches: repeat applications with changed details; VPN and data-centre traffic gets an extra step.

    Try it →

  • Referral cashback

    One person opens account after account with fresh mobile numbers to collect the sign-up cashback.

    Catches: many sign-ups from one device; the account opens, the cashback doesn't.

    Try it →

  • OTP and SMS pumping

    A script floods your OTP page with requests to premium-rate numbers, and you pay for every SMS.

    Catches: too many OTPs or numbers from one device, and bots.

    Try it →

  • Sign-in

    Leaked username and password pairs replayed one account after another.

    Catches: many failed sign-ins from one device, bots; new or risky devices get an OTP.

    Try it →

How each demo works

  1. When you press the button, the page calls the Deepvue web SDK once: DeepvueImprint.collect().
  2. It sends the device ID and Deepvue's verdict with the form to a small demo server.
  3. The server looks up this device's earlier requests and applies the demo's rules.
  4. What your backend sees shows the server's view, and The code shows the rule that ran.
